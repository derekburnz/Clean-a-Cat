What was decided and why, newest at the bottom. Append, never rewrite: when a decision changes, add a new line that says what it replaces. On a merge conflict keep both sides, main's first.

## Decided
2026-11-23: Art style is Bubble Pastel colours (cream #FFF6EC, mint #A8E6CF, bubblegum #FFB3C7, sky #8FD3FE, mud #5A4632) on the blocky chibi shapes of Derek's asset library, written up in `docs/art/style-guide.md`. Why: the blocky cat body is already approved by Derek and proven on phones, flat colours cost no texture memory, and dark mud stands out on every coat, which is the whole first 15 seconds. Derek can swap to Cozy Storybook or Bright Toy. (Model-Agent, recommended pick while Derek's answer is pending)
2026-11-23: Models are built by Python generators in `assets/clean-a-cat/blender/`, ported from Derek's asset library (derekburnz/Roblox-Asset-Library, models/blender-generators), and ship as Part-built `.model.json` files in `assets/clean-a-cat/rbx/`. Why: a style change is a code edit and a rebuild, and Part models load in a group-owned game with no mesh uploads. Only the cat body code is shared with Cat Cafe; every Clean a Cat cat has its own name and coat. (Model-Agent)
2026-11-24: Draft UI screens live as HTML mockups in `assets/clean-a-cat/ui/screens/` and pass `check.mjs` at seven screen sizes before any Luau port. Why: gameplay is not locked, and mockups are cheap to change while the gate rules stay the same. (Design-Agent, on Derek's ask)
2026-11-24: The helper cat is named Suds, not Pip. Why: Pip is already a customer's name. (Design-Agent)
2026-11-24: Odds have no setting. Settings shows "Odds on boards: always shown" as an info line, and the recap's New! tag sits beside the rarity tag under the cat's name. Why: a switch that cannot switch confuses kids (Review-QA), and Derek saw the New! sticker overlap the star badge. (Design-Agent)
2026-11-24: No word on any screen renders under 14 real px (a UITextSizeConstraint with MinTextSize 14 in the build). Cat names stay at 11 letters or fewer, and coin counts over 999,999 show short (1.2M, 3.4B). Why: the ui-review rule for body text; the screens are tested to fit 11-letter names and 999,999 coins on a 667 x 375 phone. (Design-Agent)
2026-11-24: Tools and skills to add after the open source deep dive: Roblox's own Studio skills for device and speed checks (#178), roblox-dev-skill 2.23.0 (#179), the izzyfrm UI rule files plus EL4CTEO's roblox-ui and roblox-input (#180), Roblox's built-in text size, see-through, input and safe area settings in every screen (#181) and one named low end test phone with Roblox's speed rules as the budget (#182, which waits on Derek to name the phone). Why: they cost little, add no code to the game and help every screen from the first one. The list with licenses and upkeep is `library/Planning-Agent/tools-and-skills-deep-dive.md` in the library repo. (Derek, on Planning-Agent's list)
2026-11-24: No UI framework for now (Fusion, Vide, React Luau). Why: the check gate builds every screen in a stand-in for Roblox and a framework would have to run there first, nobody has published phone speed numbers for any of them and Fusion's Wally package lags its main branch. If a list screen such as the Cat Index gets painful in plain code, trial Vide on that one screen. (Derek, on Planning-Agent's pick)

Trove (#184) is tried on one screen and kept only if it does no harm and adds no step for threads. Why: Derek wants to see each one before it stays. (Derek)
2026-11-24: Asphalt is not adopted. Why: the upload workflow and the threads already do that job. (Derek)

2026-11-24: The opening (draft, Derek's idea): a delivery truck hits a bump and a plain brown box falls in front of the new player; inside is a muddy kitten who is washed in the tutorial and becomes Suds, the spa mascot, on four paws (not standing). (Derek's idea and calls via the coordinator; drafted by Design-Agent with Planning-Agent)
2026-11-24: Dev first, live on the owner's word. Merges to main publish to the dev copy of the game only; the live place gets a build only when Derek confirms it on dev and says to send it (publish.yml with target live and the tested commit). Switches and restarts take the same dev or live target, and dev keeps the draft switches on. Why: Derek: "everything can always get uploaded to dev then when I confirm its good then we send that to live". (Derek)
2026-11-24: A server reads every switch at once when it starts, and anything decided once per join (the opening box, the owner replay) waits for that first read. Why: the switches were read one by one over 6 to 7 seconds, so the first player in a new server, Derek's live test, got every switch as off and missed the opening. (Gameplay-Engineer)
2026-11-25: The design is agreed: Clean a Cat is a busy cat spa with a cat collection. The player picks the next cat from a bench, washes it by hand in 3 to 10 steps by dirt level, reveals its coat for the Cat Index, hires workers (Jo and Sam for coins, Lou as a pass) and collects pets from crates that are earned rarely or bought with Robux with the chances shown. Waiting cats leave when their heart bar is empty, paid skips sit on every build, the starter pack runs a real 72 hour countdown, six players share a server and other players can walk into a spa unless its owner turns that off. The one page design is `docs/design/clean-a-cat/gdd.md`. Why: it is the owner's playstyle pick after nine playtests and his answers to all 65 plan questions, joined to the one thing lasting games share, which is something to collect. (Derek, written up by Planning-Agent)
2026-11-26: The Second Tub costs 60 coins, not 90, so the first short build lands after about 5 cats (about 5:30) instead of 8:20. Why: a fresh save earns about 16 coins a cat in the first session, not the 23 the tuning table expected, and a visible upgrade inside the first minutes serves the fun first five minutes goal; the build stays at 15 s so no Finish now price shows (issue 660, tuning.md sections 8 and 15).
